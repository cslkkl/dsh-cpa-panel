## 2. 重点项确认

### 2.1 workbuddy（养号能力最全，是本方案的主渠道）
- 签到：上游 `POST /v2/billing/meter/daily-checkin`，状态/连续 streak 在 `checkin.go`；管理路由 `POST /v0/management/plugins/workbuddy/checkin`。
- 任务：成长中心每日循环七连（`taskcenter.go:16` 注释：accept pending → ... → claim rewards），`tasks_auto` 默认随签到 tick 自动跑（`taskcenter.go:43-45`）。
- 领取：三层次——任务奖励（tasks/run 内含 claim）、活动券（school/vouchers，有活动窗口门控）、Global 试用包（/trial）。
- 保活：`keepalive.go:3-6` 自述动机——上游定期杀 Keycloak offline session，不主动刷 token 就 12153 全账号 401。这是**养号必需项**，不是可选。
- 生命周期：`lifecycle.go`——CN 积分耗尽自动 disabled、签到回积分后自动恢复；Global 一次性额度直接删号。

### 2.2 trae
- 签到存在且默认自动（`main.go:492` `checkin_auto` default true，09:00），仅 CN/SOLO-CN 变体；**Intl 无签到**（PROTOCOL.md trae-intl 节明确「签到：无」；intl 路由只有 accounts/status/import，`management.go:98-100`）。
- 无任务、无 voucher/school 类领取路由。
- 签到鉴权契约复杂（Cloud-IDE-JWT 优先 + req_source 1→2 双探测，9074 回退），是"必须在插件内"的原因。

### 2.3 qoder
- 签到已从 legacy daily-check-in 迁到 campaigns 系统（`campaign.go` 1327 行 + `checkin.go` 862 行），CN/Intl 同构。
- **cf5f6af 与签到/首登奖励的关系**：旧 IDE 协议登录永远触发不了服务端新人福利（14 天 Pro + 300 Credits）；v0.8.45 改官方桌面客户端 v0.4.3 协议（client_id `732aef47-...`）后，**登录事件本身即触发器**。即"首登奖励"养号动作 = 用对协议登录，不需要额外端点；日常签到 = campaigns claim。
- 领取：`POST /claim-pro` 一次性 Pro 升级包。无任务。

### 2.4 zcode
- 无每日签到、无任务。
- **领取类能力存在但性质不同**：`/claim` 是「试用套餐领取」（billing/claim，需要用户浏览器过阿里云验证码铸 verify param），`claim_scheduler.go` 是其自动调度，`offpeak.go` 是错峰优惠通道。归为养号能力 = **试用包/优惠领取**，不是每日打卡。
- 轮 4 估算的"可砍 offpeak+claim+panel ≈2250 行"在养号主功能下**反转：这正是要保留的核心**（panel.go 711 + claim.go 272 + claim_scheduler.go 283 + offpeak.go 691 + preview.go 292 ≈ 2250）。

### 2.5 mimo
- 面板页仅 2 个登录补登路由（`management.go:57 /oauth_submit`、`:59 /cookie_submit`），全仓库无 checkin/claim/task/keepalive 代码。**养号矩阵全空**——养号方案中删渠道，仅当中转渠道保留（如需要 MiMo 转发）。

## 3. 养号保留面建议

### 必须保留（养号主功能核心）
| 渠道 | 保留面 | 理由 |
|---|---|---|
| workbuddy | **全部五项**（签到+任务+领取+保活+调度器） | 五插件中唯一同时具备每日签到、任务循环、活动领取、token 保活的渠道；`keepalive.go` 不做会批量 401 |
| qoder | 签到（campaigns）+ claim-pro 领取 + keepalive + 登录协议（cf5f6af 桌面协议） | 首登奖励靠登录协议触发；日常靠 campaigns 自动领 |
| trae | CN 签到（checkin_auto） | 养号侧 Intl 无能力可养；Intl 仅保留转发 |

### 可选（按账号池情况）
- **zcode 的 claim/claim_scheduler/offpeak**：若账号是新注册需要薅试用包 → 保留；若账号已是付费套餐老号 → 可砍。验证码侧车（captcha_pool）依赖用户浏览器铸参，自动化程度低于其他三渠道，UI 上建议做成手动按钮而非全自动。
- **workbuddy 的 school/vouchers**：活动窗口型（`school.go`：窗口外 `in_period=false` 自动门控），保留代码但 UI 可折叠为"活动"分组。

### 删除
- **mimo 全渠道养号面**（本就没有任何东西）；仅在需要 MiMo 转发时保留插件本身。
- trae 的 Intl 变体养号期待（无）；zcode 的每日签到期待（无）。

### UI 养号开关设计映射
| UI 开关 | 对应插件配置/路由 |
|---|---|
| 自动每日签到 | workbuddy `/checkin/config`（:152）、qoder `/checkin/config`（:123）、trae `checkin_auto` 配置字段（main.go:492） |
| 自动做任务 | workbuddy `tasks_auto`（taskcenter.go:45，默认 on） |
| 自动保活 | workbuddy schedulerLoop 22:00 tick（内置，无独立开关） |
| 自动领取试用包 | zcode `claim_scheduler`（claim_status 路由 :307 可看状态） |
| 手动一键领取/签到 | 各 `/checkin`、`/claim-pro`、`/claim`、`/tasks/run` 按钮直挂 |
