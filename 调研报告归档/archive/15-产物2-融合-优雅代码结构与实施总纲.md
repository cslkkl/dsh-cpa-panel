**三条主数据流**：
1. **调用链（按单元）**：DSH 应用 → `/v1/chat/completions`（带单元 apiKey）→ 宿主 access 校验 → key→unit 命中 → `WithPinnedAuthID(ctx, unit.authID)` → `requestExecutionMetadata` 写 `pinned_auth_id` → selector 只认该 auth（conductor_selection.go:1203/1295）→ 插件 executor（或内置 openai_compat）→ 上游 SSE → 宿主逐帧回流。
2. **养号链**：插件 `schedulerLoop`（workbuddy checkin.go:29，0 点签到 + 22 点保活）→ 插件内部调上游签到/任务/领取端点；DSH 配置页也可手动触发（`POST /checkin`、`POST /tasks/run`、`POST /claim` 等经 `/api/v1/cpa/*` 宿主路由 → `/v0/management/plugins/<provider>/*`）。
3. **首启链**：插件启用 → `bootstrap.ts` 定位 exe/dll → SHA-256 校验 → 生成最小 `config.yaml`（随机 secret-key、plugins.enabled、oauth.auth-dir、checkin_auto/tasks_auto、disable-control-panel: true）→ `process.ts` 拉起（非 shell spawn + Job Object）→ healthz/readyz 探活 → 状态条回显。

## 3. 模块边界与依赖方向（防屎山规则）

1. **宿主（Go）**：`api`(装配/路由) → `handlers/management` → `config`+`pluginhost`+`watcher`+`access`+`sdk/cliproxy/auth`；**禁止**：`cmd` 反向 import `internal/api` 以外的业务逻辑；删除面（tui/store/discovery/translator 大部/内置 executor）不得保留任何"留但不导出"的僵尸 import（匿名 import 必须连根拔，main.go:38 逐个裁决）。
2. **插件集（Go）**：每插件自含 `go.mod`，依赖 SDK `v7.2.30` 固定；**协议实现与 C ABI 胶水分层**（借鉴 workbuddy-bridge-0.1.2-source 的 wire.go 纯函数边界：URL/header/body 组装无 host call、可单测）——实施时在各渠道重构中把 `client.go` 类混杂文件拆成"纯协议层 + 管理/调度层"；**不合并仓库、不改 provider id、不做浏览器登录收养**（养号需要桌面协议登录触发首登奖励）。
3. **DSH 插件（TS）**：`index.ts`(装配/路由) → `units.ts`(纯数据，可单测) + `process.ts`(进程) + `bootstrap.ts`(首启)；`adapters.ts`(渠道差异表，纯数据)；`client/client.js` 只经 `/api/v1/cpa/*` 与宿主半端通信，**不直接调上游**；宿主半端是唯一持 adminKey/密钥方（沿用 client.js:11 铁律注释）。
4. **跨仓库依赖方向**：DSH 插件 →（HTTP loopback）→ CPA 宿主 →（C ABI）→ 插件 dll →（HTTPS）→ 上游。**反向一律禁止**。

## 5. 接口面（导出 vs 私有）

- **导出（契约级，必须稳定）**：
  - 插件 C ABI：`cliproxy_plugin_init` 及两张函数表（ABIVersion=1，产物 2-A 附录）；
  - 插件 management 端点（产物 2-B 附录，DSH 直接引用）；
  - 宿主 `/v1` OpenAI 兼容面 + `/v8|/v0/management` JSON + `/healthz` + `/readyz`；
  - DSH 插件宿主路由 `/api/v1/cpa/*`（status/units/plugins/accounts/start/action/auto-checkin/scheduler-mode/account-enabled）。
- **私有（不导出）**：`unitMapping`、`Ready()`、DSH 的 `keyToUnit` 内部映射、插件的 session/签名内部函数、`ACTION_PATHS.*.refresh/trial/import/release/claim*`（留但不导出路由，UI 不暴露）。
- **删除（明确"删"）**：见各详案废接口清单（宿主 §5、插件集 §4、DSH §4），含 `/v1/images|videos|realtime|v1beta`、OAuth 回调、`management.html`、`/api/v1/cpa/{school,routing,priority}`、`RoutingSection`、`activeAuthOf`、mimo 全量。

## 6. 错误处理与日志规范

- **宿主**：沿用 logrus 现状（不引入 slog 重构，避免破坏 906 测试基线）；错误码语义——管理面无 key→404、错 key→401（限流封禁沿用）、插件未加载→503（/readyz）、单元 key 命中但 auth 禁用/冷却→`auth_not_found`（不 failover）；配置解析失败→保留旧值（原子写+回滚语义）。
- **DSH 插件**：错误"行内错误条 + role=status"不擦屏；整屏 error→保留上次数据+顶部错误条；未知值渲染 null 不摆假 0；行级 busy 锁（ReadonlySet）防连点；错误色一律 `--dsw-alias-state-error-primary`；探活超时挂状态条原因文案（运行中/停止/启动中/崩溃+crashExitCode）。
- **日志**：宿主日志落 `./logs/`（自动建）；DSH 插件侧不做日志持久化，状态经 `/status` 回显；首启每步打点（校验失败/生成 config/拉起/探活）供排查。
