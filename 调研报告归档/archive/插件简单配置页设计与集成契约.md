# 插件简单配置页设计与集成契约

- 调研对象：`dsh-cpa-panel@0.1.0` @ `7da7da8`（承接第一轮《解剖与 TS 迁移评估》）
- 新约束：① 只保留「简单配置页」（模型选择 / 启用渠道 / 检查项勾选），复杂面板（余额、签到、任务批量）倾向全删；② 只做 Windows
- 方法：只读；上一轮的 16 条宿主→CPA 调用清单为代码事实，CPA 端点形态以官方 Management API 文档为准["https://help.router-for.me/management/api"]
- **重要勘误先行**：题面提到的 `/v8/management/config` 不存在。CPA Management API 的 base path 是 **`/v0/management`**（官方文档：`http://localhost:8317/v0/management`）；鉴权 `Authorization: Bearer <key>` 或 `X-Management-Key`，与本插件 `cpaFetch`（index.js:168-194）一致["https://help.router-for.me/management/api"]。全局配置读写是 `GET /v0/management/config`；插件级配置是 `PATCH /v0/management/plugins/{id}/config`。

## 1) 配置页字段清单（逐字段：去留 / 对应 CPA 端点 / 后端保留能力）

> 关键事实：DSH 的 schemastery `Config` schema **本身就会被宿主渲染成设置表单**（index.js:48-56 注释：`.volatile()` 字段才进表单）。因此「简单配置页」的绝大多数字段**不需要任何前端代码、不需要任何 `/api/v1/cpa/*` 路由**——它们是纯配置项，由宿主表单读写，宿主在 `apply` 里现读（`refs.xxx.get()`，index.js:217-226）。

| 字段 | 类型/默认 | 去留 | 对应 CPA 端点 | 后端要保留的能力 |
|---|---|---|---|---|
| `adminKey` | string(secret) `''` | **保留（必需）** | 不打端点；是所有请求的 Bearer 来源 | `resolveAdminKey`（index.js:234）+ `cpaFetch` 头注入 |
| `adminKeyRef` | string `'CPA_ADMIN_KEY'` | **保留（必需）** | 无 | `ctx.credentials.resolve(credentialRef(...))`（index.js:240） |
| `port` | natural `8317` | **保留（必需）** | baseURL `http://127.0.0.1:<port>` 的来源（index.js:169） | `probePort`/baseURL 拼接 |
| `exePath` | string `''` | **保留**（Windows only 下探测候选仍有用） | 无 | `resolveExe` + `defaultExeCandidates`（index.js:84-94,265） |
| `manageLifecycle` | bool `true` | **保留（必需）** | 无（控制 spawn） | `ensureRunning`/`stopIfOwned`（index.js:275,321） |
| `openControlPanel` | bool `false` | 可保留为勾选项 | 无（控制 `-no-browser` 参数，index.js:302） | spawn args |
| `startTimeoutSeconds` | natural `30` | 保留（高级项，可折叠） | 无 | `waitForPort` |
| `autoCheckinOnStart` | bool `true` | **保留（检查项）** | 触发 `POST /v0/management/plugins/{id}/checkin`（开机补签，index.js:360） | `runStartupCheckin`（index.js:340） |
| **`enabledChannels`（新增）** | multiselect `[workbuddy,trae,qoder,zcode]` | **新增** | 见下两种语义 | 见下 |
| **`defaultModel`（新增，存疑）** | string/select | **存疑，建议不做** | 插件现有能力只有**读**：`GET /v0/management/plugins/{id}/models/groups?refresh=1`（zcode 为 `/models`）（index.js:578-604）；**没有任何写端点** | 仅 `modelsOf` 只读列表 |
| `checkin_auto`（自动签到开关） | bool | **保留为勾选项** | 读：`GET /v0/management/plugins/{id}/accounts` 顶层 `checkin_auto`；写：`PATCH /v0/management/plugins/{id}/config` body `{"checkin_auto":bool}`（AUTO_CHECKIN_PATHS，adapters.js:242-254） | `autoCheckin`（index.js:552） |

**关于 `enabledChannels` 的两种语义（必须先选一种）：**

- **语义 A——只是面板可见性**：不打 CPA，纯插件本地配置，`PLUGIN_ORDER` 过滤即可。零新端点。
- **语义 B——真正停用该渠道**：对应官方上游端点 `GET /v0/management/plugins`（列出各插件 `plugins_enabled`/`effective_enabled`）与 **`PATCH /v0/management/plugins/{pluginID}/enabled`**["https://help.router-for.me/plugin/development"]。⚠️ 这两个端点**当前插件的 16 条调用里完全没有用到**，是需要新增的后端能力。若要「勾选=CPA 真的不跑这个号池」，走语义 B。

**关于「模型选择」的现实判断**：DSH 自己有模型选择器；本插件对模型只有只读目录（`models/groups?refresh=1`），写模型别名/排除模型属于 CPA 全局 `/config` 的 `excluded-models`/`models.alias` 维度["https://help.router-for.me/management/api"]，与「简单配置页」目标相悖。**建议：模型选择不在本插件做**；若一定要展示，复用现有只读 `/models/groups`，不发明写接口。

## 2) 现有面板功能逐项 verdict

| 功能 | verdict | 理由 / 牵连端点 |
|---|---|---|
| 余额展示（可用/已用/额度池/套餐包） | **可删** | 依赖 `GET /accounts` + `GET /credits` + `normalizeAccounts`（adapters.js:280）；纯展示，无配置价值 |
| 一键签到（全部） | **面板按钮可删** | 但 `POST /plugins/{id}/checkin` **端点不能删**——开机补签（`runStartupCheckin` index.js:340）仍要用它 |
| 一键任务（全部） | **可删** | 仅 `POST /workbuddy/tasks/run`，无配置语义 |
| 单账号签到/任务 | **可删** | `action(plugin,kind,authIndex)` 的 authIndex 分支（index.js:458-461）随按钮一起删 |
| 刷新（面板 reload / CPA 侧 refresh） | **可删** | 面板 reload 是前端行为；CPA 侧 `POST /plugins/{id}/refresh`（ACTION_PATHS）只服务面板 |
| 拖拽排序（priority） | **可删** | `PATCH /v0/management/auth-files/fields`（index.js:795）+ 整套 drag UI；属复杂交互，不符合「简单配置页」 |
| 自动签到开关（checkin_auto） | **建议保留**，从面板开关降级为配置页勾选项 | 它本身就是 bool 勾选，天然适合简单配置；端点现成（见 §1） |
| 活跃账号检测 | **可删** | `GET /auth-files` 读 `recent_requests`（index.js:485），纯观测 |
| **进程生命周期（CPA 随 DSH 启停）** | **不能删（开箱即用必需）** | `ensureRunning`/`stopIfOwned`/`spawn`（index.js:275,321,303）。没有它，插件只是个空壳，CPA 不会自己起来 |
| **密钥管理（adminKey/adminKeyRef）** | **不能删（开箱即用必需）** | 缺密钥所有写操作 401；`resolveAdminKey`（index.js:234）是整个插件的门禁 |
| 开机补签 | **保留**，由既有 `autoCheckinOnStart` 勾选控制 | 已有配置项，行为自动 |
| 路由策略 / scheduler_mode 归一 | 可降级为「检查项/一键修复」（见 §4），不必常驻面板 | `GET/PUT /routing/strategy`、`PATCH /plugins/{id}/config`（index.js:624,661,698） |

## 3) client.js 简化形态

### 3.1 12 条 `/api/v1/cpa/*` 路由的去留

| 路由 | 去留 |
|---|---|
| `GET /api/v1/cpa/status` | **保留**（运行态/密钥是否就绪的唯一指示） |
| `GET /api/v1/cpa/auto-checkin` | **保留（瘦身后）**——checkin_auto 勾选的读写 |
| `POST /api/v1/cpa/start` | 可选保留（手动补启动按钮） |
| `GET /api/v1/cpa/models?plugin=` | 仅当 §1 的「模型选择」真做才保留；否则删 |
| `GET /api/v1/cpa/plugins` | 可删（插件清单可静态写死，或并入 status） |
| `accounts / school / routing / scheduler-mode / priority / action / account-enabled` | **全删**（对应面板功能已删） |

→ 从 12 条砍到 **2~4 条**，且其中一半只是状态查询。

### 3.2 UI 复杂度估算

- 纯 schema 驱动：配置表单由宿主按 `Config` 自动渲染，**自定义 React ≈ 0**；client.js 只剩一个可选的「运行状态行」（StateDot + 端口 + 密钥就绪提示）。
- 若加模型下拉：需要一个异步 select 组件（一次 fetch `/models/groups`），复杂度约相当于原 client.js 的 5%。
- 原 client.js 1111 行（卡片网格、拖拽排序、进度条、toast、内联 CSS 200 行）几乎全部删除。

### 3.3 TS 迁移结论复核（与第一轮的差异）

- **第一轮结论**：宿主半端转 TS、浏览器半端因 `__ModuleLoader__` CJS bundle 形态保留 JS。
- **本轮复核**：面板删掉后出现更优解——
  - 配置表单由宿主 schema 渲染，**两个 `ctx.slots.inject`（plugins.detail.section / settings.plugins.tab，client.js:1074,1092）可以整体摘除**；卡片标题/描述本就在 `locale/*.json`，不依赖 client.js 内联字典。
  - **若「模型选择」不做**：`client.js` 整个文件可删，`package.json` 的 `dsh.client`/`exports["./client"]` 同步去掉 → 插件退化为**纯宿主半端**。此时根本没有 `__ModuleLoader__` 依赖，「client 必须留 JS」的约束自动消失，**全 TS（index.ts + adapters.ts）成为唯一形态，无混合分界问题**。
  - **若坚持模型下拉**：才需要保留一个极小的 JS client bundle（维持 CJS factory 形态），混合方案不变。
- **判断**：推荐走「无 client bundle」路线——简单配置页与 DSH 原生设置表单同构，不必自造 UI，TS 迁移也最干净。

## 4) 「检查项」候选清单（每项对应端点）

| 检查项 | 现实性 | 对应端点 / 判据 |
|---|---|---|
| CPA 进程在跑（TCP 连通） | ✅ 已实现 | 不打 HTTP：`probePort`（net.createConnection 127.0.0.1:port，index.js:132） |
| Management API 可用 + 密钥有效 | ✅ 新增（便宜） | `GET /v0/management/config`（或 `/plugins`）：200=密钥对且 API 活着；401/403=密钥错；连接拒绝=CPA 没起。比 `/v1/models` 更合适——见下 |
| 自动签到 checkin_auto 是否开启 | ✅ 已实现 | 读 `GET /v0/management/plugins/{id}/accounts` 顶层 `checkin_auto`（adapters.js:245） |
| 开机补签 | ✅ 已实现（本地勾选） | 插件本地 bool；触发 `POST /plugins/{id}/checkin` |
| scheduler_mode=off 归一（优先级生效前置） | ✅ 可做一键修复 | `GET /plugins/{id}/config` 读 → `PATCH /plugins/{id}/config` body `{"scheduler_mode":"off"}`（index.js:661）；注意**改完要重启 CPA** |
| 路由策略 = fill-first | ✅ 可做 | `GET /v0/management/routing/strategy` 读；`PUT` body `{"value":"fill-first"}`（index.js:698） |
| 渠道插件是否就绪（workbuddy.dll 等） | ✅ 可做 | `GET /v0/management/plugins` 列 `plugins_enabled`/`effective_enabled`["https://help.router-for.me/plugin/development"]——勾选「启用渠道」时顺便展示未安装渠道 |

**对题面三个猜测的裁定：**

1. **`/v8/management/credentials/refresh`** —— 路径不存在；实际对应物是 `POST /v0/management/plugins/{id}/refresh`（已在 ACTION_PATHS，adapters.js:209 等）。它只是个面板动作，不建议进简单配置页。
2. **`/v1/models` 探活** —— 端点真实存在（`GET http://localhost:8317/v1/models`，OpenAI 兼容面）["https://www.mintlify.com/router-for-me/CLIProxyAPI/quickstart","https://deepwiki.com/router-for-me/CLIProxyAPI/4.1-openai-compatible-endpoints"]，**但它要的是代理业务 api-key（`api-keys`），不是管理密钥**；本插件只持有 adminKey，拿它探活要么另存一个业务 key、要么匿名（多数部署 401）。**健康检查优先用 `GET /v0/management/config`（adminKey 即可），不要用 /v1/models**。
3. **checkin_auto 自动签到开关** —— 真实且已实现，列为检查项首选。

## 附：结论速记

- 简单配置页 ≈ 纯 schemastery schema（adminKey/port/exePath/manageLifecycle/autoCheckinOnStart/checkin_auto/enabledChannels），宿主自动渲染；**不能删**的是进程生命周期与密钥管理。
- 模型选择建议不做（DSH 自带；插件只读不写）。
- 路由从 12 条砍到 2~4 条；client.js 可整体删除 → **全 TS 化不再有 client 侧障碍**。
- 健康检查用 `GET /v0/management/config`（adminKey），不要用 `/v1/models`。
- 端点版本是 `/v0/management`，不是 v8。
