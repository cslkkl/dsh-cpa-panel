## 〇、压缩结论（先读）

**基线全部对得上**：五仓库基线 commit 与蓝图声明一致（CLIProxyAPI@local-autobrowser/c121fde/v8/go1.26.0；cpa-multi-plugins@cf5f6af；dsh-cpa-panel@7da7da8；dsh-workbuddy-bridge@2b2992d；workbuddy-bridge-0.1.2-source@a1536df）。**锚点行号命中率极高**（抽查 ~50 处，约 95% 精确命中，少数 1 行偏移均为注释/空行所致）。

**但不能直接进实施**，原因有四：
1. **一处高层矛盾（H1）**：插件自带的 `panel.html/panel.go` 到底删还是留——产物 2-A 与大白话版要删，产物 2-B 与融合总纲要留，R5「唯一 UI=DSH 插件页」与之冲突。不裁决则实施者两分叉。
2. **删除面清单不完整（M2/M3）**：`main.go` 还 import 了 4 个蓝图只字未提的包（browser/misc/registry/safemode）；`internal/runtime/executor` 是扁平目录，蓝图的前缀 glob 漏列若干共享文件；codex executor 在 `service_executors.go:203/235/252` 的 switch 外另有分支，且 `server.go:23` import `codex/live`——删包后这些会编译报错。
3. **思考强度「默认 medium」无强制落点（M4）**：插件代码只做 strip/透传，客户端不传时不会注入 medium；蓝图未指定谁把默认值写进出站请求。
4. **首启失败分支矩阵不全（M5）**：下载失败 / 端口占用 / 已在跑 / spawn 秒崩均无定义。

**最终判定：修订后进入实施**（非「可直接进入」，亦非「必须推倒重来」）。先做一次裁决 + 补清单，再开工。

## 二、发现的问题清单（按严重度）

### 高（必须先裁决，否则实施分叉）

**H1｜插件自带 panel.html / panel.go 去留自相矛盾**
- 位置：产物 2-A §2.1 删除面（列「workbuddy panel.html/panel.go UI」随「内置 UI 全删」）↔ 产物 2-B §2.1/§2.2（workbuddy/qoder 保留面明确写 `management.go + panel.go + panel.html`）↔ 融合 §2.2（同样保留）↔ 大白话版 §3（砍「插件自带面板页」）。
- 矛盾点：R5 要求「CPA 内置 UI 全删，唯一 UI=DSH 插件页」。但 2-B/融合要保留各渠道插件的 `panel.html`（经 `/v0/resource/plugins/<id>/panel` 提供）。2-A 与大白话版要删，2-B 与融合要留。
- 影响：实施者若按 2-A 删 panel.go/panel.html，则与 2-B 保留面冲突、且 zcode 验证码铸 verify param 依赖面板页（V28 链路）；若按 2-B 留，则违背「唯一 UI=DSH」。zcode 的阿里云验证码本就在插件面板页内完成，删面板会断 zcode 领取链路。
- 修正建议：明确二选一——(a) 插件面板页仅保留为「zcode 验证码 + OAuth 回调」的技术性 HTML（非养号 UI），DSH 插件页为唯一养号操作面；或 (b) 承认插件面板页仍为补充 UI，放宽 R5 措辞。需拍板。

- 位置：2-C §6.3 全局 `reasoningEffort` 默认 `'medium'`、§6.2 单元 `reasoningEffortDefault`；但插件侧——workbuddy `payload.go` 的 `mirrorReasoningEffort` 只 strip none/off、trae `payload.go:219` 只透传显式值——**客户端不传 reasoning_effort 时，没有任何代码会注入 medium**。

## 六、最终判定

# **修订后进入实施**

**理由**：
- 事实层过硬——五仓库基线全对、抽查 ~50 处行号约 95% 精确命中、钉号链/端点注册/SDK 版本/工程范本全部静态核验通过，架构方向（三仓独立、Go 只瘦身、TS 半端、单元钉号、养号主线）自洽。
- 但存在 1 个高层矛盾（H1）+ 5 个中级缺口（M1-M6），其中 H1 不裁决会让实施者在「删/留插件面板」上两分叉，M2/M3 会在 S1 编译阶段反复返工，M4/M5 会在 S5/S7 联调才暴露。

**进实施前必须先做的 5 件事**（按序）：
1. **裁决 H1**：插件 panel.html/panel.go 是降级为「zcode 验证码+OAuth 回调技术页」还是承认其为补充 UI，并统一 2-A/2-B/融合/大白话版措辞。

3. **补全删除面（M2/M3/M6）**：main.go 四包去留表 + codex pre-switch 分支与 server.go codexlive 连带改点 + executor 扁平目录逐文件清单 + openControlPanel 三兄弟函数。
4. **闭环 M4**：明确 reasoning_effort 默认 medium 的注入点（建议 DSH 转发层兜底）。
5. **补全 M5**：bootstrap/process 状态机五失败分支（下载失败/端口占用/已在跑/秒崩/校验失败）。

完成上述修订后，S0-S7 可按产物 3 分包顺序推进；S1 与 S3 并行、S4 依赖 S1 契约的依赖关系已在任务书中写对，无需调整。
