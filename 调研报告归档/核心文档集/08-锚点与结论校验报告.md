## 2. 机制结论 · 证伪检查（两项实测定论）

### 机制① 「DSH 对话直选模型」链路 —— **成立，非伪**

04 §5.3 声称链路 = `inject:['llm']` + `ctx.llm.registerAdapter` + pi-ai `createProvider` + `PiAiAdapter`。逐环实测：

| 环 | 文档声称 | 实测 | 判定 |
|---|---|---|---|
| a 注入 | `inject:['llm']`（index.ts:181） | `export const inject = ['llm']` | ✅ 真 |
| b 注册 | `ctx.llm.registerAdapter([variant.id], workbuddy.adapter)`（:699） | 逐字命中 | ✅ 真 |
| b 组装 | adapter 由 pi-ai `createProvider({id,name,models,api})` + dsh-llm-pi-ai `PiAiAdapter` 组装（adapter.ts:252-307） | `createProvider` 来自 `@earendil-works/pi-ai`(:9/:252)；`PiAiAdapter` 来自 `@deepseek-ai/dsh-llm-pi-ai`(:22)，实例化为 `WorkBuddyPiAiAdapter`(:290) | ✅ 真 |
| c 不注册目录项 | 刻意不 registerConfigurableProviders（:688-698） | 注释块逐字命中 | ✅ 真 |
| d 回发 | `ctx.emit('llm/adapters-updated')`（:685） | 逐字命中 | ✅ 真 |
| e picker 提交 | `{provider, model:id, reasoningEffort}`（:104） | 注释逐字命中 | ✅ 真 |
| f baseUrl/apiKey | `baseUrl=${shim.baseUrl()}/v1`（:248）；`resolveApiKey=shim.token()`（:297） | 逐字命中 | ✅ 真 |
| g 显示名折计费 | `withCatalogDisplay(name,info)`（:124-127） | 逐字命中 | ✅ 真 |

**定论**：机制为真，04 §5.3 七环证据链完整、无一环被证伪。cpa-panel 照此复制（每渠道一个 pi-ai provider，baseUrl 指向 `127.0.0.1:8317/v1`）在工程上成立。**残留风险（非本机制证伪）**：04 §5.3 末尾 V3 自标的「CPA 能否按 model id 钉 auth」仍需运行时实测——本校验轮为静态对照，无法证伪该运行时行为，维持 04/06 的 V3/U3 待验证标注。

### 机制② `dsh.client.inject` 漏 primitives —— **定论：确属漏列，必须补**

| 事实 | 实测 | 判定 |
|---|---|---|
| cpa-panel inject 清单 | package.json:41-44 = `[dsh-client-ui-settings, dsh-client-ui-plugin-manager]`，**无 primitives** | 缺口客观存在 ✅ |
| cpa-panel client.js 是否 require primitives | client.js:34 `require('@deepseek-ai/dsh-client-ui-primitives')` | 确有 require ✅ |
| **bridge 范本 inject 是否列 primitives** | bridge package.json:77 **明确列** `@deepseek-ai/dsh-client-ui-primitives` | 范本是列的 ✅ |
| client.js:26-29 注释主张 | 注释称 primitives 在宿主 `PLATFORM_MODULES` 静态表、**无需** inject，并举「官方 dsh-client-ui-plugin-manager 就这么用」 | 该主张**无法在本轮三仓内证实**，且与 bridge 实践相悖 |

**定论**：
1. `dsh.client.inject` **客观漏列** `dsh-client-ui-primitives`（事实缺口，非文档臆测）。
2. 04 §1.3「必须补进 inject，否则新增 Modal/Checkbox/writeClipboard 后注入不全」的结论**正确，应维持**。
3. client.js:26-29「无需 inject」注释**不可作为豁免依据**：它（a）依赖本轮三仓无法验证的宿主 `PLATFORM_MODULES` 静态表与 plugin-manager 行为；（b）与**实际在用的范本 bridge** 明确 inject primitives 的做法直接矛盾。现有 Button/Switch/Tag/Pill/StateDot 能跑，不代表未来新增组件也能经静态 fallback 解析。
4. 02 F3 的「⚠待核对/与 2-C §5 冲突」到此**裁决完毕**：**按「必补」执行**，client.js 注释需在 TS 化时改写，不得沿用「无需 inject」的误导表述。
