## 2. 已锁定方向（不可推翻，除非用户明确改）

1. **主功能 = 养号自动化**（签到/领取/做任务/保活）。
2. **独立调用单元**：渠道×账号×模型 = 1 单元；每单元独立 API key（`units[].apiKey`）；用宿主原生 `pinned_auth_id` 钉号，**绝对锁定单账号不混用**；账号不可用直接报错不顶替。
3. **思考强度默认 medium**：请求带 reasoning_effort/thinking → 按渠道能力映射/透传；无 → 默认 medium（每单元可覆盖）；不报错。注入点 = DSH 宿主半端转发层按 `units[].reasoningEffortDefault` 兜底写入，插件不背此责。
4. **CPA 内置 UI 全删**（management.html/panel.html/assets），唯一养号/管理操作界面 = DSH 插件页。插件渠道自带的 panel.html/panel.go 保留为**技术页**（zcode 验证码铸参 + OAuth 回调载体），不出新 UI 入口。
5. **只做 Windows、无 Docker、单 exe**；插件 dll 从 Release 预编译分发（SHA-256 校验），用户机零工具链。
6. **DSH 宿主零改动**，一切通过插件实现（cordis.patch.yml 机制照旧）。
7. **三/五仓库独立、不合并**；垃圾零容忍（废接口/废函数/改名），唯一例外=无源码的 .dll 等二进制。
8. **R13 删除面**：插件渠道（WorkBuddy/Qoder/Trae/ZCode）的登录协议、auth 文件、验证流程**全部保留**（在 cpa-multi-plugins 插件集内）；宿主内置 provider 族（`internal/runtime/executor/{claude,codex,gemini,kimi,xai,devin,meta,antigravity,vertex,aistudio}*`、`sdk/auth/{claude,codex,codex_device,devin,kimi,meta,xai,antigravity}.go`、`internal/browser`）**全部删除**。

## 3. 主代理独立核查（4 项新发现）

> 性质：MainAgent 直接 Grep/Read 五仓库真实源码的第二道验证线（与组织者复查互补）。
> 锚点核验 11 项全中（行号/函数名/端点注册/SDK 版本），可信度高；以下 4 项为影响方案精度的新发现。

### 发现 1（利好）：model_execution.go AuthID 捷径

`sdk/api/handlers/model_execution.go:115/151` 原生支持 `req.AuthID != "" → ctx = WithPinnedAuthID(ctx, req.AuthID)`。

→ key→unit 映射实现路径比原详案更顺：只需把单元 key 解析出的 authID 作为请求 AuthID 传入，宿主新增代码收敛至约 5–10 行，可能不碰 access 中间件。实施时优先评估此捷径。

### 发现 2（删除面补全）：config_load.go:223 第三原子写点

`internal/config/config_load.go:223` `os.WriteFile(configFile, cleaned, 0600)`（配置加载清洗后回写）——与 config_yaml.go:102、auth_files_crud.go:272 同属 config 写路径。原子写补丁从 ×2 扩为 ×3，工作量仍 <30 行。

### 发现 3（生命周期佐证）：插件 shutdown no-op + SIGSEGV 风险

`plugins/workbuddy/checkin.go` 顶部注释原文：插件 shutdown export 是 no-op，因为宿主在自身 runtime teardown 时调用它，从插件 c-shared runtime 触碰 Go sync 原语会在每次重启时 SIGSEGV。

→ DSH 插件停 CPA 时**不要依赖插件 shutdown 清理调度器**；进程终止走「shutdown 端点 → Ctrl-C → taskkill /F 兜底」。此发现是对现有进程托管设计的佐证，非修改。

### 发现 4（依赖清单不全抄）：bridge peer 依赖 21 包 ≠ cpa-panel 所需

dsh-workbuddy-bridge 的 peerDependencies 有 21 个 @deepseek-ai 包（React 浏览器半端全家桶）。cpa-panel 方案 = client.js 保留 JS + schemastery 自动表单，**不需要 React 全家桶**。

→ peer 只需：cordis / dsh-credentials / schemastery（现状）+ 补 primitives（client.js 实际 require 但 inject 漏列）+ atomic-write（config 写）。照搬 bridge 工程骨架（tsdown/vitest/eslint/scripts），但**不照搬依赖清单**。
